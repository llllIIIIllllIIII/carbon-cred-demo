1

簽發 — 越南廠開出碳足跡憑證

Day 1 上午
① 供應鏈位置

最上游 Tier-2、整條信任鏈的源頭。程式跑在「Thép Việt 的系統」(= Tab 1 + Thép Việt 簽發鍵)。這一步不跨組織——但它簽出來的東西,後面每一幕都要驗。

② 技術細節
  • 憑證:SD-JWT VC(@sd-jwt/core + @sd-jwt/sd-jwt-vc,OpenWallet Foundation sd-jwt-js),資料模型照 UNTP DPP 0.6 欄位命名。
  • 欄位三分法:非 SD 明文 = cn_code / quantity / origin(公開層);SD 可撕欄位 = direct、route、carbon_price、indirect、installation、dqr(海關層+客戶層);機密根本不進憑證 — 只放三個 commitment hash(machine_energy_hash…)+ emission_factor_table_hash 當一般 claim。
  • 簽章鑰 = Thép Việt 的 sandbox LE AID 鑰(SD-JWT ✓ 與 vLEI 鏈 ✓ 是同一把——Codex 審查後定案);憑證以 status.status_list = {idx, uri} 掛撤銷參照(如 idx #12)。
  • [選配] RISC Zero dev mode:guest 驗 Σ(活動數據×係數)=0.42,journal 的 hash 塞進 VC 的 evidence。
③ 呈現方式

Tab 1:預填表單 → 按「簽發」→ 憑證卡出現,欄位用 🟢🟡🔴 三色標;下方印出原始 token <JWT>~<d1>~<d2>…,口白一句:「一個簽章、N 張可撕欄位」。這一幕就是把觀眾對『憑證長什麼樣』的想像釘下來。

④ 最小驗收與保底

DoD:verify() 通過;手動改 payload 一個 byte → 驗證失敗(這個失敗畫面留著,幕 6 之前有人問就秀)。

保底:簽發改成賽前 script 預簽,demo 只展示已簽好的結果卡——按鈕變成「載入憑證」,其餘不變。

聚合 — 鴻鋼疊出自己產品的憑證

Day 1 上午
① 供應鏈位置

Tier-1 內部(Tab 2 + 鴻鋼 sandbox LE 鑰)。這是命題「資料散落在內部系統與供應商之間」被接起來的位置:上游憑證(外部)+ 自家製程資料(內部)→ 一張新憑證(給下游)。

② 技術細節
  • 鴻鋼以持有者身分讀上游 VC 的完整客戶層出示(它是買方,拿得到),程式計算 1.05×1.05 + 0.08 + 0.33 = 1.51。
  • 簽發 pcf_aggregate(同樣 SD-JWT):carbon_price_paid = 台灣碳費;precursor_ref = 上游 VC 的 id + hash,不含上游任何明細欄位。
  • 疊層熱點圖 = 一個 <svg> 三段 rect,寬度綁真實計算值,不要硬寫。
③ 呈現方式

按「聚合簽發」→ 熱點圖長出三段(案 B 時上游段變紅,一眼看出超標在高爐路線)→ 新憑證卡出現。鏡頭停在一句話上:「新憑證裡沒有上游明細,只有一個參照指紋」——Tier-N 最小揭露傳遞就是這 15 秒。

④ 最小驗收與保底

DoD:聚合值由程式算出、圖用真值渲染;換 seed(案 A→B)圖跟著變。

保底:SVG 退成兩張靜態圖(A 版/B 版)切換。

委任與查驗 — 跨組織的主線

Day 1 下午 ★核心
① 供應鏈位置

唯一橫跨三個位置的一幕:Bruck 側簽 mandate(Tab 3)→ 請求跨過組織邊界進鴻鋼閘道(Tab 2 的 Cedar)→ presentation 回到 Bruck 側本地離線驗證。信任邊界被跨了兩次,這正是 Track 01 的題眼。

② 技術細節
  • M2 mandate = 一般 JWT(jose 就夠,不需 SD),由 Bruck 永續長 sandbox ECR 鑰簽;欄位照 spec §5.2:allowed_claims×6、granularity=batch、query_cap、jti / mandate_nonce / delegate_kid(綁 bruck-workload 鑰)、policy_version、status.status_list。每次查驗請求由 workload 鑰簽章並附新的 request_nonce——閘道對 (mandate_id, request_nonce) UNIQUE,重送 → REPLAY_DETECTED;query_cap 扣次與 presentation、稽核同一交易;驗證結果以 context.mandate_status_ok / delegate_key_ok / replay_ok 三布林餵入 Cedar,**政策不直接讀 mandate 狀態**。
  • 閘道:Cedar P1(@cedar-policy/cedar-wasm 的 authorize)判 PERMIT → 後端以持有端身分從上游 SD-JWT 挑出 allowed_claims 對應的 disclosures,組 presentation 回傳。重點:是「挑 disclosure」,不是「過濾 JSON」。
  • Bruck 端驗證三件事:簽章(用 Thép Việt/鴻鋼公鑰,不呼叫鴻鋼 API)、vLEI 鏈(讀 data/vlei/ 預簽檔)、Status List(抓 /status/* 的 compact JWT,先驗 JWS 簽章 → 解碼 status_list.bits/lst → 查 idx)。Key-binding JWT 不做 → 治理缺口頁。
③ 呈現方式

Tab 3:mandate 卡(六個 claim chips 醒目)→ 按「發出查驗」→ 切 Tab 2 看一眼 PERMIT · P1 → 切回 Tab 3:presentation 卡只有六列,旁註「其他欄位連遮罩都沒有——不存在於這份文件」→ 驗證面板三個綠勾 + OFFLINE 標籤(錄影時開飛航模式或拔 API,口白帶一句)。

④ 最小驗收與保底

DoD:斷網狀態驗證仍成功;故意在 allowed_claims 外多挑一個 disclosure → Bruck 端政策檢查報 CLAIM_NOT_IN_MANDATE(雙向約束)。

保底:cedar-wasm 裝不起來 → 手寫 policy.ts 純函式,但畫面照樣顯示 Cedar 規則原文並標注「引擎簡化」。SD-JWT 是本幕不可退讓的底線。

越界攔截 DENY

Day 1 下午 ★高潮
① 供應鏈位置

同幕 3 的組織邊界上,但停在鴻鋼閘道內——請求進來、被擋、只有「拒絕 + 理由碼」出去,一個資料欄位都沒離開。

② 技術細節
  • Cedar P2 forbid:claim.tag == "confidential" 一律拒絕,不看 mandate 寫什麼(forbid 優先於 permit 是 Cedar 內建語意,Q&A 可以講)。
  • Deny 也產 decision + audit entry,同一筆 DB 交易寫入;理由碼 POLICY_P2_CONFIDENTIAL。
③ 呈現方式

Tab 3 按那顆紅色的「加碼索取 machine_energy」→ Tab 2 出現旋轉紅章 DENY + P2 規則原文高亮 → 底部稽核帶即時多一行並閃一下。鏡頭定格在理由碼三秒。這 20 秒是整支錄影剪輯的錨點。

④ 最小驗收與保底

DoD:deny 事件能被 verify-chain.ts 驗到(證明「連拒絕都留痕」)。

保底:無。這幕成本最低、分數最高,必做。

稽核與撤銷 REVOKED

Day 2 上午
① 供應鏈位置

橫跨全部:稽核帶屬於鴻鋼閘道、撤銷清單屬於各簽發者(Bruck 撤 mandate、Thép Việt 撤憑證)、重驗發生在所有驗證方。這幕證明的是「事後有人能抓、事中有人能拔插頭」。

② 技術細節
  • audit_chain:entry_hash = sha256(prev_hash ‖ payload_hash ‖ ts) + workload 鍵簽收據;verify-chain.ts 從頭走一遍;tamper.sh = 一行 sqlite UPDATE 改歷史某筆。
  • Token Status List(draft-ietf-oauth-status-list-21):compact signed JWT,header.typ="statuslist+jwt",payload 含 sub/iat(建議 exp/ttl)與 status_list = { bits: 1, lst: base64url(zlib 壓縮位元陣列) };端點回 application/statuslist+jwt;保底 = 裸 bit array JSON(明確標示 fallback)。revoke.ts --list mandates --index 7 重寫檔案。
  • 兩種撤銷都演:撤 mandate → 重跑案 A 得 MANDATE_REVOKED;撤上游憑證 → 已放行 Dossier 標記 depends_revoked(查 credentials 引用鏈)——紡織版搬來的回溯戲。
③ 呈現方式

切到終端:verify-chain 全綠 → ./tamper.sh 42 → 重驗,#42 起紅字 FAIL(竄改無所遁形)。回 Tab 4:bit 條 …0 0 [1] 0… 翻轉 → 重跑案 A,紅章 MANDATE_REVOKED → Dossier 列表浮出黃 badge「依據已撤銷,需重驗」。口白補一句 vLEI 撤銷向下連鎖。

④ 最小驗收與保底

DoD:撤銷不重啟服務即生效(驗證方每次現抓 status);tamper 後能一鍵還原(備份 db 檔)。

保底:status list 用裸 JSON;hash chain 驗證只跑終端不做 UI 表格。
