## 1. Repo 策略細節

### 1.1 為什麼 vendor 而不是 submodule / 外部引用

- **submodule**:上游追蹤乾淨,但 `clone --recursive` 忘記就是空資料夾、CI 要額外設定、隊友踩坑機率高。本專案生命週期四天,上游(2 個 commit)不會有要追的更新。
- **外部路徑引用**(sibling clone + 環境變數):交件 repo 不自足,「在我機器上可以跑」風險最高。
- **vendor**:`vendor/vlei-sandbox/` 整包複製,保留上游 LICENSE(MIT),新增 `VENDOR.md` 記錄來源 URL 與釘死的 commit hash。會場斷網也能 presign。**採用。**

規則:vendor 目錄視為唯讀,**不改動上游任何檔案**;所有整合寫在 `server/` 或 `scripts/` 的包裝層。

### 1.2 金鑰與狀態的衛生規則(.gitignore 必含)

```
.vlei/            # sandbox 狀態,內含私鑰種子——絕不進版控
data/keys/        # 兩把 app 產生的 workload 私鑰(組織/個人鑰在 .vlei/)
db/*.sqlite*      # 資料庫檔
node_modules/  .venv/
```

### 1.3 SAID 漂移與 manifest 機制(重要)

presign 每台機器重跑一次,產出的 SAID 都不同。因此:

- `scripts/presign-vlei.sh` 結束時寫 `data/vlei/manifest.json`:`{ role → { alias, kind, legal_name, aid, lei, credential_said, presentation_file, public_key } }`;v3 為 **7 個角色**:`yarn / fab / dye / brand / cb`(LE)+ `fab_cfo / brand_cso`(ECR)。
- **公鑰是公開材料,必進 manifest**:M2 驗簽、BRAND 端驗證、任何鏈檢查都靠它;私鑰仍只存在 `.vlei/`。
- **seed、後端、前端一律讀 manifest 取 SAID,任何地方不得寫死 SAID。**
- `data/vlei/` 內只放公開材料(presentation 包 + manifest),可進版控;私鑰留在 `.vlei/`。

## 3. Runtime 架構與信任邊界三原則

單一 Fastify 程序(:3000)+ Vite dev server(:5173,proxy `/api`、`/status`)。單程序演五家公司,靠以下三條紀律讓宣稱成立(寫進 CLAUDE.md,違反即 bug):

1. **一方一鑰,一律經 `server/keys.ts` key loader。** 組織/個人鑰自 sandbox 匯出、workload 鑰 app 產生;route 不得直接讀鑰檔或 `.vlei/state.json`。
2. **BRAND 端驗證零依賴閘道。** `verify` 只讀:token 本身、公鑰、`data/vlei/` 呈現包、`data/status/*.jwt`(**先驗 compact JWS 簽章,再解碼 `payload.status_list.bits/lst`,最後查 idx**)。不呼叫 `/api/disclose` 以外的任何內部狀態;同一份邏輯打包成 `scripts/verify-offline.ts`,錄影時斷網執行。
3. **決策與稽核同交易。** 所有 PERMIT/DENY/RELEASE/REPLAY_DETECTED 都經 `server/audit.ts` 唯一入口寫入(`decisions` + `audit_chain` 同一筆 better-sqlite3 transaction);DENY 也不例外。

簽章身分清單(**組織/個人鑰一律經 `server/keys.ts` 自 `.vlei/state.json` 匯出;workload 鑰由 app 產生於 `data/keys/`**):

| 簽章身分 | 來源 | 用在 |
|---|---|---|
| YARN(紗廠)LE 鑰 | sandbox 匯出 | 幕 1 簽 `tc_carbon_upstream`(SD-JWT ✓ 與 vLEI 鏈 ✓ 同一把鑰) |
| DYE(染整廠)LE 鑰 | sandbox 匯出 | 幕 2 輸入 `pcf_dyeing`、幕 5 `invoice`;**幕 6 撤銷主線的簽發者** |
| FAB(布廠)LE 鑰 | sandbox 匯出 | 幕 2 簽 `pcf_aggregate`;Status List Token 簽發(閘道為兩份清單發布方) |
| FAB 財務主管 ECR 鑰 | sandbox 匯出 | 簽 M1;**幕 5 人工放行簽核**(人=ECR,放行簽名鏈回公司) |
| BRAND 永續長 ECR 鑰 | sandbox 匯出 | 簽 M2(kid = 她的 AID) |
| CB(認證機構)LE 鑰 | sandbox 匯出 | 加映 `slcp_dcc`、[選配] 查證聲明 VC |
| fab-workload.key | app 產生 | Agent-1 Dossier 簽章、稽核收據(payload 含 git commit hash);**M1.delegate_kid 綁定此鑰** |
| brand-workload.key | app 產生 | Agent-2 的 disclose request 簽章;**M2.delegate_kid 綁定此鑰** |

**全域 Plan B**(Phase 0 已判定 Plan A 成立;若新增 `dye` 匯出失敗才啟動):該身分改為 `data/keys/` app 鑰 + manifest 內綁定聲明 + 治理缺口頁標注;demo 流程與 API 零改動。

## 4. API 面(route × 幕)

| Route | 幕 | 說明 |
|---|---|---|
| `POST /api/issue/upstream` | 1 | 經 `server/keys.ts` 載入 **YARN sandbox LE AID 鑰**簽 `tc_carbon_upstream`(TE camelCase 鍵名 + `pcf_*`);機密欄僅 commitment hash |
| `POST /api/issue/dyeing?case=A|B` | 2(前置) | 經 key loader 載入 **DYE LE 鑰**簽 `pcf_dyeing`;`pcf_direct/indirect/total` 由係數表計算(熱源 × 鍋爐效率 × 係數;電 × 0.474 × (1−綠電比)) |
| `POST /api/aggregate?case=A|B` | 2 | 讀紗憑證與染整憑證(消費前皆驗章)→ 計算 `紗×1.0545 + 2.4×0.474 + 染整` → 經 key loader 載入 **FAB LE 鑰**簽 `pcf_aggregate`;`precursor_refs` 兩筆 id+hash |
| `POST /api/mandates` | 3 | 簽 M1(財務主管 ECR)/ M2(永續長 ECR);delegate_kid 綁對應 workload |
| `POST /api/disclose` | 3/4 | 閘道:①驗 request 簽章(對 mandate.delegate_kid)②驗 request_nonce——`(mandate_id, request_nonce)` UNIQUE,重複 → `REPLAY_DETECTED` ③驗 mandate 本體(簽章、iss/aud/exp/jti、Token Status List)→ 產出 `context.mandate_status_ok / delegate_key_ok / replay_ok` ④Cedar P1/P2 **只消費上述可信布林與 mandate 資料欄位** → 挑 disclosures 組 presentation(`pcf_yarn/pcf_knitting/pcf_dyeing` 永遠挑不出);**query_cap 扣次與 presentation、audit 同一筆交易**;DENY/REPLAY 走同稽核路徑 |
| `POST /api/verify` | 3 | BRAND 端:SD-JWT 驗簽 + child_process vLEI verify + Status List(**先驗 compact JWS 簽章 → 解碼 → 查 idx**)+ receipt 綁定 |
| `POST /api/agent/run?case=A|B|C|Cp` | 5 | P3 要件管線(DYE 身分 / `pcf_aggregate.pcf_total ≤ 9500 gCO₂e/kg` / 發票 / 收款帳戶風險雙來源)→ Dossier(fab-workload 簽) |
| `POST /api/human-sign` | 5 | **財務主管以其 sandbox ECR 鑰**簽署放行(不建立 human.key);產 **mock USD 電匯指令**(付款人 FAB、收款人 DYE、USD 3,420)→ 狀態 RELEASED |
| `POST /api/revoke` | 6 | 包裝 scripts/revoke.ts(翻 bit + 重簽 Status List JWT)與 sandbox revoke(TEL);撤 `pcf_dyeing` 後:重跑案 A → `CREDENTIAL_REVOKED`;既有 Dossier 依 `precursor_refs` 標 `DEPENDS_REVOKED` |
| `POST /api/issue/dyeing?case=A&reissue=1` | 6 | DYE 重簽(新 `pcf_period`、新 idx)→ `POST /api/aggregate` 重聚合 → 重驗綠 |
| `GET /api/audit?after=` | 全 | 稽核帶輪詢(以最後 seq 為游標) |
| `GET /status/*` | 3/6 | 回傳 **compact signed Status List JWT**;`Content-Type: application/statuslist+jwt` |
| `GET /api/report/draft` | 3(**選配**) | 把已驗證的品牌層六欄渲染成 Higg FEM / 品牌系統填報草稿 JSON(取代 v2 的 CBAM 申報草稿);「送出」按鈕僅 UI 佔位並強制人工確認 |

## 7. 風險與緩解

| 風險 | 緩解 |
|---|---|
| 會場網路差 | vendor + `make setup` 全離線可跑(npm 依賴賽前先 `npm i` 進 lockfile 快取機) |
