## 1. Repo 策略細節

### 1.1 為什麼 vendor 而不是 submodule / 外部引用

- **submodule**:上游追蹤乾淨,但 `clone --recursive` 忘記就是空資料夾、CI 要額外設定、隊友踩坑機率高。本專案生命週期四天,上游(2 個 commit)不會有要追的更新。
- **外部路徑引用**(sibling clone + 環境變數):交件 repo 不自足,「在我機器上可以跑」風險最高。
- **vendor**:`vendor/vlei-sandbox/` 整包複製,保留上游 LICENSE(MIT),新增 `VENDOR.md` 記錄來源 URL 與釘死的 commit hash。會場斷網也能 presign。**採用。**

規則:vendor 目錄視為唯讀,**不改動上游任何檔案**;所有整合寫在 `server/` 或 `scripts/` 的包裝層。

### 1.2 金鑰與狀態的衛生規則(.gitignore 必含)

```
.vlei/            # sandbox 狀態,內含私鑰種子——絕不進版控
data/keys/        # 兩把 app 產生的 workload 私鑰(組織/個人鑰在 .vlei/)
db/*.sqlite*      # 資料庫檔
node_modules/  .venv/
```

### 1.3 SAID 漂移與 manifest 機制(重要)

presign 每台機器重跑一次,產出的 SAID 都不同。因此:

- `scripts/presign-vlei.sh` 結束時寫 `data/vlei/manifest.json`:`{ role → { alias, aid, lei, credential_said, presentation_file, public_key } }`
- **公鑰是公開材料,必進 manifest**:M2 驗簽(選項 A)、Bruck 端驗證、任何鏈檢查都靠它;私鑰仍只存在 `.vlei/`。
- **seed、後端、前端一律讀 manifest 取 SAID,任何地方不得寫死 SAID。**
- `data/vlei/` 內只放公開材料(presentation 包 + manifest),可進版控;私鑰留在 `.vlei/`。

## 3. Runtime 架構與信任邊界三原則

單一 Fastify 程序(:3000)+ Vite dev server(:5173,proxy `/api`、`/status`)。單程序演四家公司,靠以下三條紀律讓宣稱成立(寫進 CLAUDE.md,違反即 bug):

1. **一方一鑰,一律經 `server/keys.ts` key loader。** 組織/個人鑰自 sandbox 匯出、workload 鑰 app 產生;route 不得直接讀鑰檔或 `.vlei/state.json`。
2. **Bruck 端驗證零依賴閘道。** `verify` 只讀:token 本身、公鑰、`data/vlei/` 呈現包、`data/status/*.jwt`(**先驗 compact JWS 簽章,再解碼 `payload.status_list.bits/lst`,最後查 idx**)。不呼叫 `/api/disclose` 以外的任何內部狀態;同一份邏輯打包成 `scripts/verify-offline.ts`,錄影時斷網執行。
3. **決策與稽核同交易。** 所有 PERMIT/DENY/RELEASE 都經 `server/audit.ts` 唯一入口寫入(`decisions` + `audit_chain` 同一筆 better-sqlite3 transaction);DENY 也不例外。

簽章身分清單(**組織/個人鑰一律經 `server/keys.ts` 自 `.vlei/state.json` 匯出;workload 鑰由 app 產生於 `data/keys/`**):

| 簽章身分 | 來源 | 用在 |
|---|---|---|
| Thép Việt LE 鑰 | sandbox 匯出 | 幕 1 簽 `pcf_upstream`(SD-JWT ✓ 與 vLEI 鏈 ✓ 同一把鑰) |
| 鴻鋼 LE 鑰 | sandbox 匯出 | 幕 2 簽 `pcf_aggregate` |
| 鴻鋼財務主管 ECR 鑰 | sandbox 匯出 | 簽 M1;**幕 5 人工放行簽核**(人=ECR,放行簽名也鏈回公司) |
| Bruck 永續長 ECR 鑰 | sandbox 匯出 | 簽 M2(kid = 她的 AID) |
| hunggang-workload.key | app 產生 | Agent-1 Dossier 簽章、稽核收據(payload 含 git commit hash);**M1.delegate_kid 綁定此鑰** |
| bruck-workload.key | app 產生 | Agent-2 的 disclose request 簽章;**M2.delegate_kid 綁定此鑰** |
| (選配)台驗 LE 鑰 | sandbox 匯出 | `rba_dcc` 與查證聲明 VC(Phase 3 選配) |

**全域 Plan B**(Phase 0 timebox 90 分鐘內 state.json 解析失敗時啟動):上表 sandbox 來源全數改為 `data/keys/` app 鑰 + manifest 內綁定聲明 + 治理缺口頁標注;demo 流程與 API 零改動。

## 4. API 面(route × 幕)

| Route | 幕 | 說明 |
|---|---|---|
| `POST /api/issue/upstream` | 1 | 經 `server/keys.ts` 載入 **Thép Việt sandbox LE AID 鑰**簽 SD-JWT;機密欄僅 commitment hash(不為公司另建 app key) |
| `POST /api/aggregate` | 2 | 讀上游客戶層 → 計算 → 經 `server/keys.ts` 載入 **鴻鋼 sandbox LE AID 鑰**簽 pcf_aggregate |
| `POST /api/mandates` | 3 | 簽 M1/M2(key loader 依 A/B 選項) |
| `POST /api/disclose` | 3/4 | 閘道:①驗 request 簽章(對 mandate.delegate_kid)②驗 request_nonce——`(mandate_id, request_nonce)` UNIQUE,重複 → `REPLAY_DETECTED` ③驗 mandate 本體(簽章、iss/aud/exp/jti、Token Status List)→ 產出 `context.mandate_status_ok / delegate_key_ok / replay_ok` ④Cedar P1/P2 **只消費上述可信布林與 mandate 資料欄位,不直接讀 mandate 狀態** → 挑 disclosures 組 presentation;**query_cap 扣次與 presentation、audit 同一筆交易**;DENY/REPLAY 走同稽核路徑 |
| `POST /api/verify` | 3 | Bruck 端:SD-JWT 驗簽 + child_process vLEI verify + Status List(**先驗 compact JWS 簽章 → 解碼 payload.status_list.bits/lst → 查 idx**) |
| `POST /api/agent/run?case=A|B|C|Cp` | 5 | P3 四要件管線 → Dossier(workload 簽) |
| `POST /api/human-sign` | 5 | **財務主管以其 sandbox ECR 鑰**簽署放行(不建立 human.key);產 mock 付款指令(USDC 為合成幣別) |
| `GET /api/declaration/draft` | 3(**選配**) | 依 UNTP/PACT→CBAM 對照表,把已驗證的六欄渲染成 CBAM 申報草稿 JSON;「送出申報」按鈕僅 UI 佔位並**強制人工確認** |
| `POST /api/revoke` | 6 | 包裝 scripts/revoke.ts 與 sandbox revoke |
| `GET /api/audit?after=` | 全 | 稽核帶輪詢 |
| `GET /status/*` | 3/6 | 回傳 **compact signed Status List JWT**;`Content-Type: application/statuslist+jwt`(裸 JSON bit array 僅為明確標示的 fallback) |

## 7. 風險與緩解

| 風險 | 緩解 |
|---|---|
| 會場網路差 | vendor + `make setup` 全離線可跑(npm 依賴賽前先 `npm i` 進 lockfile 快取機) |
| blake3 裝不起來 | sandbox 自動退 Blake2b(識別碼 `F` 開頭);功能不受影響,錄影前務必確認裝成功以得 `E` 開頭 |
| SAID 換機器漂移 | manifest.json 機制(§1.3);seed 絕不寫死 SAID |
| `.vlei/state.json` 金鑰格式與預期不符 | Phase 0 timebox 90 分鐘;啟動**全域 Plan B**(app 鑰 + manifest 綁定聲明 + 缺口標注),demo 流程與 API 零改動 |
| cedar-wasm 環境問題 | `server/policy/` 內建退路:policy.ts 純函式 + 前端仍顯示 .cedar 原文,治理缺口標注「引擎簡化」 |
| KERI 純度質疑(「私鑰不該離開錢包」) | 治理缺口頁一行:「mock 模式下 state 檔即錢包,由持有人金鑰直接簽署;production 應由 KERIA/錢包端簽署,或為 Agent 建立委派 AID——sandbox 的 `--delegator` 機制已示範同一原理」。把質疑變成預埋的伏筆 |
| 錄影中狀態污染 | `make demo-reset` 一鍵還原;錄影 SOP 第一步固定執行 |
