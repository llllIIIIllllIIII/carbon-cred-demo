1

簽發 — 認證機構開 TC,紗廠開碳憑證,兩張綁在一起

已完成 · 遷移換欄位 + 多一張 CB 憑證
① 供應鏈位置

最上游 Tier-2、整條信任鏈的源頭,而且一開始就跨兩個組織:認證機構 Lowland(CB)簽 Transaction Certificate、越藍紗業(YARN)簽碳足跡憑證,兩張都在 Tab 1 出現。產業現況:每交一筆貨由賣方的認證機構開一張 TC(CCS-102 E2.1,簽發前審文件與數量勾稽),半紙本半 PDF,而且 TC 裡沒有碳數據(Textile Exchange 官方文件確認)——碳只有紗廠自己的帳單能證明。

② 技術細節
  • 兩張憑證,兩把鑰(v3.1):tc_rcs 由 CB 的 sandbox LE 鑰簽,欄位照 Textile Exchange TC 的 camelCase 鍵名原樣(tcNo、tcProductStandardLabelGrade、tcProductCertifiedWeight、inputTcNo、seller/buyer…)加 volume_reconciled: true(E2.1.8 數量勾稽的結果宣告);pcf_upstream 由 YARN 的 sandbox LE 鑰簽,公開層帶 tc_ref = {id, hash: sha256(tc_rcs)} 綁住那張 TC——TC 不存在就拒簽。
  • 欄位三分法(pcf_upstream):非 SD 明文 = tc_ref、產品碼、產地 VN;SD 可撕欄位 = pcf_total 3.00、pcf_period、quantity_kg(品牌層)+ pcf_direct 0.42 / pcf_indirect 2.58、係數來源(稽核層);機密根本不進憑證 — 單價、電費帳單、回收粒供應商名只留 commitment hash + emission_factor_table_hash。tc_rcs 的成分比例、認證重量、inputTcNo 為品牌層 SD,發票號只留 hash。
  • 兩把都是 sandbox LE AID 鑰(SD-JWT ✓ 與 vLEI 鏈 ✓ 同一把);Status List idx:tc_rcs 9、pcf_upstream 0(A)/ 1(B);A/B 兩案紗憑證相同。
  • pcf_indirect = 3.91 kWh × 越南電網 0.6592,由程式算,不寫死;布廠幕 2 會核對 tc_ref 的 hash、seller/buyer LEI 與認證重量 ≥ 批次數量,不符 → TC_REF_MISMATCH。
③ 呈現方式

Tab 1:先出現卡 1「Transaction Certificate — Lowland 簽發」(TE 鍵名原樣、volume_reconciled ✓)→ 按「簽發碳足跡憑證」→ 卡 2 出現,公開層的 tc_ref 旁一個鏈結圖示指向卡 1,欄位用 🟢🟡🔴 三色標;下方印出原始 token。口白:「TC 是認證機構開的但沒有碳;碳只有紗廠有帳單能證明;我們把兩條信任鏈綁在一起。」

④ 最小驗收與保底

DoD:兩張都 verify() 通過(分別用 CB、YARN 的 manifest 公鑰);手動改 tc_rcs 一個 byte 再簽 pcf_upstream → 幕 2 聚合回 TC_REF_MISMATCH;presentation 只能挑出 SD 欄位,🔴 項目連 disclosure 都不存在。

保底 (a)(交接檔三):8/30 中午前 tcRcs.ts 未完成 → 不簽 TC 憑證,紗廠憑證的 tc_ref = {tcNo, issuer_lei, hash(seed 的 TC JSON)} 純參照,憑證卡標一行「本憑證不是 TC;TC 由 CB 簽發,此處以編號 + hash 引用」,治理缺口頁註明 CB 憑證未真簽;口白不變。再退一步:簽發改成賽前 script 預簽,按鈕變成「載入憑證」。
Δ v2 → v3
改:CBAM 欄位 → pcf_* + 新的 CB 簽 tc_rcs(TE 鍵名);pcf_upstream 檔名保留、加 tc_ref;單位 tCO₂e/t → kgCO₂e/kg;A/B 差異不再在這一幕(紗憑證相同);CB 進主線。不改:簽發流程、三分法、SD 機制、Status List 引用。
2

聚合 — 布廠疊出自己產品的憑證(三段)

已完成 · 遷移改公式為三輸入
① 供應鏈位置

Tier-1 內部(Tab 2 + FAB 的 sandbox LE 鑰),但輸入來自三個外部組織:認證機構的 TC 與布廠自己的 Scope Certificate、紗廠的碳憑證、外包染整廠的 pcf_dyeing,加上自家織布的用電。這是命題「資料散落在內部系統與供應商之間」被接起來的位置:三張外部憑證 + 一張 SC + 內部製程 → 一張新憑證(給下游)。CCS-102 D3.4:外包染整廠要嘛自己有 SC、要嘛列在布廠 SC 上受稽核——demo 走後者。

② 技術細節
  • 新增 pcf_dyeing(DYE 的 sandbox LE 鑰簽):公開層帶 ccs_scope_ref = {sc_no, hash} 指向布廠的 SC;pcf_direct = 48.6 MJ ÷ 鍋爐效率 × 燃料係數、pcf_indirect = 1.8 kWh × 0.474 × (1 − 綠電比)。A 案天然氣 + 30% 綠電 = 3.63;B 案燃煤 = 6.60。鍋爐型號、燃料合約、化學品清冊、PPA 價格只留 hash。
  • 新增 ccs_scope_cert(v3.1;CB 的 sandbox LE 鑰簽,seed 時簽一次):布廠 SC LLC-SC-2026-0142,製程 針織,associated_subcontractors = [彩合染整 / dyeing_finishing / audited],效期一年;全部公開層。
  • FAB 以持有者身分讀三張外部憑證的完整揭露,消費前先以 manifest 公鑰驗章(驗不過就 CREDENTIAL_SIG_INVALID,不得跳過),再核對兩條綁定:pcf_upstream.tc_ref.hash == sha256(tc_rcs)、seller/buyer LEI、認證重量 ≥ 批次數量(不符 → TC_REF_MISMATCH);pcf_dyeing.ccs_scope_ref.sc_no == SC 且 DYE LEI 在 SC 分包商清單、SC 有效(不符 → CCS_SUBCONTRACTOR_NOT_LISTED / SCOPE_CERT_INVALID)。然後程式計算 紗 3.00×1.0545 + 織布 2.4×0.474 + 染整 = 7.93 / 10.90。
  • 簽發 pcf_aggregate(同樣 SD-JWT):品牌層六欄(pcf_total、pcf_period、pcf_method、成分比例、verification、quantity_kg);三段拆解 pcf_yarn / pcf_knitting / pcf_dyeing 為稽核層 SD 且 NEVER_DISCLOSABLE;precursor_refs = 三張外部憑證的 id + hash,不含任何上游明細;公開層帶 ccs_scope_ref,tcProductStandardLabelGrade(RCS 100)由 tc_rcs 的 label grade + 有效 SC 推導,不再自填;全廠產量、產能利用率、品牌別分配比、月度帳單承諾值只留 hash。
  • 疊層熱點圖 = 一個 <svg> 三段 rect(紗 / 織布 / 染整),寬度綁 API 回傳的真值與門檻 9.5,不要硬寫。
③ 呈現方式

按「聚合簽發」→ 熱點圖長出三段(案 B 時染整段變紅、整條越過門檻線,一眼看出超標在外包染整的燃煤鍋爐)→ 新憑證卡出現。鏡頭停在一句話上:「下游拿到的憑證裡沒有紗廠是誰、沒有染整廠帳單,只有三個參照指紋和一張認證機構簽的 SC」——Tier-N 最小揭露傳遞就是這 20 秒。

④ 最小驗收與保底

DoD:聚合值由程式算出、圖用真值渲染;換 seed(案 A→B)只有染整段變、圖跟著變;precursor_refs 恰三筆且 hash 對得上入庫的 sd_jwt;清空 SC 分包商清單重灌 → 聚合回 CCS_SUBCONTRACTOR_NOT_LISTED。

保底:SVG 退成兩張靜態圖(A 版/B 版)切換;若受訪者回覆染整在自家,DYE 併入 FAB 自簽內部段憑證,SC 的製程改列針織 + 染整、分包商清單為空,公式與圖不變。
Δ v2 → v3
改:兩輸入 → 三輸入 + SC(多外部 pcf_dyeing、CB 的 tc_rcs 與 ccs_scope_cert);A/B 差異從上游移到染整段;台灣碳費欄位退場,改以再生能源比與 verification 表達;precursor_ref → precursor_refs[] ×3;新增 tc_ref / ccs_scope_ref 核對與三個理由碼。不改:消費前驗章、算術洩漏防線(H2)、熱點圖走伺服端真值。
3

委任與查驗 — 跨組織的主線

已完成 ★核心 · 遷移只換六欄
① 供應鏈位置

唯一橫跨三個位置的一幕:品牌側簽 mandate(Tab 3)→ 請求跨過組織邊界進布廠閘道(Tab 2 的 Cedar)→ presentation 回到品牌側本地離線驗證。訪談實況:品牌今天在 Worldly 上看到的是供應商自報的總量,年度再派第三方到廠核單據;我們讓總量帶著證明,而且品牌拿不到能反推產能的欄位。

② 技術細節
  • M2 mandate = 一般 JWT(jose),由 BRAND 永續長的 sandbox ECR 鑰簽;purpose = brand_scope3_supplier_reporting;allowed_claims 六欄 = pcf_total · pcf_period · pcf_method · tcProductRawMaterialPercentage · verification · quantity_kg(排放數字恰一個);jti / mandate_nonce / delegate_kid(綁 brand-workload)/ query_cap 10 / status.status_list。
